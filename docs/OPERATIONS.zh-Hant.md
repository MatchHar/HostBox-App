# 更新、備份、回復和復原

[English](OPERATIONS.md) · [简体中文](OPERATIONS.zh-Hans.md) · [繁體中文](OPERATIONS.zh-Hant.md)

## 更新政策

HostBox 提供的是已驗證穩定目錄中的版本，不一定是上游最新版本。進入穩定目錄前，
必須通過全路徑相容性、連線、備份、健康和回復驗證。HostBox 會另行提示上游新版本，
但不會跟隨可變的 latest 標籤。

更新前確認可用空間、穩定 SSH、供應商快照或異地備份，並安排維護時段。HostBox
操作期間不要同時手動更新多個元件。

## 備份模型

更新受支援的堆疊前，HostBox 會先建立並驗證 PostgreSQL 自訂格式備份，同時儲存
復原所需的目前部署設定。備份驗證失敗時，升級會在服務切換前停止。

這項交易性備份不等於完整災難復原方案。請按獨立保留週期保存加密異地備份和／或
供應商快照，並定期測試還原。

## 回復行為

- 容器切換前失敗：恢復已儲存設定。
- 切換後在啟動或健康檢查階段失敗：使用配對設定和升級前資料庫復原路徑。
- 回復失敗是停止條件。保留備份和診斷，不要刪除卷宗，也不要反覆執行破壞性手動指令。

## 日常維護

- 在 HostBox 查看元件狀態以及已安裝／目標版本。
- 在明確重新啟動時段內安裝系統安全更新。
- 監控可用空間和備份保留。
- 人員／裝置變更或疑似洩漏後輪替憑證。
- 基礎設施遷移後重新驗證 DNS、TLS、Tunnel／VPN 和 SSH 指紋。
- 維護後測試 My T 連線，不要公開內部連接埠。

## 請求復原協助

只提供已移除敏感內容的版本資訊、失敗的 HostBox 步驟和概括性健康狀態。備份、
Compose、`.env`、資料庫匯出、憑證、伺服器地址和完整日誌不要進入公開 Issue。
